Section 01Poori picture

Aapne ek single-page application (SPA) banaya hai. Matlab browser sirf ek HTML file aur ek JavaScript bundle download karta hai, aur uske baad JavaScript hi screen ka content badalta rehta hai. "Hotels" pe click karne se server se nayi page nahi maangi jaati — React bas alag components render kar deta hai.

App ke do side hain, aur dono ka dimaag ek hi hai.

Sabse important baat

Jo room ek guest book karta hai aur jo room owner add karta hai — dono memory mein ek hi array hain. Owner dashboard se room add karo, phir /rooms kholo — woh wahan already dikh raha hoga. Yahi shared state hai, aur Context isko possible banata hai.

Section 05JSX — HTML jaisa dikhne wala JavaScript

JSX na HTML hai, na koi templating language. Yeh asal mein function calls ka shortcut hai. Vite isko:

<p className="text-gray-500">{room.hotel.city}</p>

lagbhag isme convert kar deta hai:

jsx('p', { className: 'text-gray-500', children: room.hotel.city })

Isi se saare rules samajh aa jaate hain jo aapko yaad karne pade the:

RuleWajahAapke code mein
className, class nahiclass JavaScript ka reserved keyword haihar jagah
htmlFor, for nahiwahi wajahHero.jsx ke labels
Ek hi root element return karofunction ek hi value return karta haihar component
{ } se JS mein jaate hoandar jo bhi hai woh ek expression hai{currency}{room.pricePerNight}
Tags self-close hone chahiye<img />, <input />HotelCard.jsx
Component ka naam capital sechhota matlab DOM tag, bada matlab aapka component<StarRating /> vs <div>

{ } ke andar aap expression daal sakte ho, statement kabhi nahi. Isiliye aapko if ki jagah ternary aur && dikhte hain:

// chalega — ternary ki ek value hoti hai
{booking.isPaid ? "Paid" : "Unpaid"}

// nahi chalega — `if` statement hai, uski koi value nahi hoti
{if (booking.isPaid) …}

Template literals se aap class strings conditionally bana sakte ho — yeh pattern aapke poore Navbar mein hai:

className={`fixed top-0 w-full ${isScrolled ? "bg-white/80 shadow-md" : "py-4"}`}

Aapka Title.jsx project ka sabse saaf example hai:

const Title = ({ title, subTitle, align, font }) => (

Section 07State — useState

Props bahar se aate hain; state component ki apni cheez hai. State woh memory hai jo re-render ke baad bhi bachi rehti hai, aur use badalna hi React ko re-render karne ka signal deta hai.

const [destination, setDestination] = useState("");
//     ↑ abhi ki value  ↑ badalne ka ekmatra tarika  ↑ starting value

Aapka Hero.jsx chaar state rakhta hai, har form field ke liye ek:

const [destination, setDestination] = useState("");
const [checkIn,     setCheckIn]     = useState("");
const [checkOut,    setCheckOut]    = useState("");
const [guests,      setGuests]      = useState(1);

Teen cheezein jahan sabhi phaste hain

1. State set karne se variable turant nahi badalta.

setGuests(3);
console.log(guests); // abhi bhi PURANI value — is render ka `guests` ek const hai

Nayi value agle render mein dikhegi. Samajhne ka aasan tarika: re-render matlab aapke component function ko dobara call karna, nayi values ke saath.

2. Jab nayi value purani pe depend karti ho, to updater function use karo. Aapne AppProvider.jsx mein yeh har jagah sahi kiya hai:

setRooms((prev) => [room, ...prev]);   // safe
setRooms([room, ...rooms]);            // purana `rooms` pakad sakta hai

3. Lazy initial state. Aapka Navbar function wala form use karta hai taaki window.scrollY sirf ek baar mount pe padha jaaye, har render pe nahi:

const [atTop, setAtTop] = useState(() => window.scrollY <= 10);

Object state: AddRoom wala pattern

Paanch alag useState ki jagah, AddRoom.jsx related fields ko ek object mein rakhta hai. Update karte waqt pehle copy, phir override karna padta hai:

const [inputs, setInputs] = useState({
  roomType: "",
  pricePerNight: "",

// ek nested amenity toggle karna — HAR level pe spread karo

Dono spread kyun zaroori hain

Section 08Events aur controlled forms

React ke events DOM events jaise lagte hain lekin hain synthetic — React inhe wrap karta hai taaki sab browsers mein ek jaisa behave karein. Inhe props ki tarah lagate ho, camelCase mein: onClick, onChange, onSubmit, onKeyDown.

Controlled inputs

Input "controlled" tab kehlata hai jab React state hi sach ka ekmatra source ho:

<input
  value={destination}                              // state → input
  onChange={(e) => setDestination(e.target.value)}  // input → state
/>

Form submit

App ka har form sabse pehle event.preventDefault() call karta hai. Warna browser poora page reload kar dega aur aapki SPA zero se restart ho jayegi:

const handleSearch = (event) => {
  event.preventDefault();          // browser ka apna submit roko
  rememberCity(destination.trim());
  const params = new URLSearchParams();
  if (destination.trim()) params.set("destination", destination.trim());
  navigate(`/rooms?${params.toString()}`);
};

Form ki chhoti-chhoti cheezein jo aapne sahi ki

  • Dates aapas mein jude hain — check-in ko check-out se aage set karo to check-out apne aap khaali ho jaata hai (Hero.jsx:84, RoomDetails.jsx:149).
  • Dynamic min — min={checkInDate || today()} se galat dates calendar mein select hi nahi hoti.
  • Jab tak valid na ho tab tak disabled — check-out disabled={!checkInDate} hai.
  • Bubbling roka gaya — HotelReg.jsx mein overlay pe onClick={close} hai lekin form pe onClick={(e) => e.stopPropagation()}, isliye dialog ke andar click karne se woh band nahi hota. Yeh modal ka standard pattern hai.

Section 10Lists render karna aur key prop

Aap arrays ko .map() se render karte ho, jo har data item ko ek element bana deta hai:

{filteredRooms.map((room) => (
  <div key={room._id}>
    <img src={room.images[0]} alt={`${room.hotel.name} room`} />
    <p>{room.hotel.name}</p>
  </div>
))}

key optional kyun nahi hai

key React ke liye list item ka pehchan-patra hai. Iske bina React sirf position se match kar sakta hai — aur jaise hi aap kuch insert, delete ya reorder karte ho, position jhoot bolne lagti hai.

Isiliye booking.js exist karta hai:

let idCounter = 0;
export const createId = (prefix) =>
  `${prefix}_${Date.now().toString(36)}${idCounter++}`;

Sirf timestamp kaafi nahi tha — ek hi millisecond mein do rooms add ho jaayein to id takra jaati. Counter uniqueness pakka karta hai. Asli app mein yeh id database deta.

Index kab chalega

Index ko key banana tab theek hai jab list kabhi reorder na ho, kabhi filter na ho, aur items ka apna koi state na ho — isiliye StarRating.jsx mein key={index} (hamesha paanch fixed stars) bilkul sahi hai.

Section 11Immutability — har update ke peeche ka rule

React yeh decide karta hai ki re-render karna hai ya nahi, purane aur naye state ka reference compare karke. Agar aap array ko jagah pe hi mutate kar do to reference wahi rehta hai — React ko lagta hai kuch badla hi nahi, aur UI chupchaap update hona band ho jaata hai.

// mutation — wahi array reference, React ignore kar dega
rooms.push(newRoom);
setRooms(rooms);

// har baar naya array
setRooms((prev) => [newRoom, ...prev]);

Chaar operations, jaise aapne likhe

KaamAapka codeKahan
AddsetRooms((prev) => [room, ...prev])addRoom
Ek ko updateprev.map(r => r._id === id ? {...r, isAvailable: !r.isAvailable} : r)toggleRoomAvailability
Removeprev.filter(b => b._id !== bookingId)cancelBooking
Nested update{...prev, amenities: {...prev.amenities, [k]: v}}AddRoom
Yeh chaar yaad kar lo

Update ke liye map, delete ke liye filter, add ke liye spread, aur nested ke liye har level pe spread. React mein aap zindagi bhar jitne bhi state updates likhoge, woh inhi chaar mein se ek honge. Dhyan do ki yeh sab non-mutating methods hain — push, splice, sort, reverse sab mutate karte hain, isliye AllRooms.jsx mein [...sorted].sort(…) likha hai, sorted.sort(…) nahi.

Section 12useEffect aur cleanup

Rendering pure honi chahiye: same props aur state andar, same JSX bahar, aur kuch bhi bahar ka haath na lage. Lekin asli apps ko bahar ki duniya chhuni padti hai — scroll listeners, timers, document body. useEffect woh darwaaza hai jo React ke paint karne ke baad chalta hai.

useEffect(() => {
  /* effect */
  return () => { /* cleanup */ };
}, [deps]);

Aapke project ka har effect

1 · Navigate karte hi upar scroll — App.jsx:23

useEffect(() => {
  window.scrollTo(0, 0);
}, [pathname]);

Iske bina, room list ke neeche se detail page pe jaate hi aap nayi page ke beech mein gir jaate. Har SPA ko yeh router ki aadat theek karni padti hai. Yahan cleanup ki zaroorat nahi — kuch subscribe hi nahi kiya.

2 · Scroll listener — Navbar.jsx:48

useEffect(() => {
  const handleScroll = () => setAtTop(window.scrollY <= 10);
  window.addEventListener("scroll", handleScroll, { passive: true });
  return () => window.removeEventListener("scroll", handleScroll);
}, []);

Yahan cleanup zaroori hai. Iske bina har remount ek aur listener chipka deta jo kabhi hatta hi nahi — memory leak jo dheere-dheere badhta rehta hai.

3 · Modal ya drawer khulne pe body scroll lock — Navbar.jsx:55, HotelReg.jsx:16

useEffect(() => {
  document.body.style.overflow = isMenuOpen ? "hidden" : "";
  return () => { document.body.style.overflow = ""; };
}, [isMenuOpen]);

Cleanup yahan bhi zaroori hai: agar menu khula hua ho aur component unmount ho jaaye, to page hamesha ke liye scroll na hone wali reh jaati.

4 · Toast ka apne aap gayab hona — AppProvider.jsx:27

useEffect(() => {
  if (!toast) return;
  const timer = setTimeout(() => setToast(null), 3500);
  return () => clearTimeout(timer);
}, [toast]);

Yeh cleanup code ko sirf saaf nahi, sahi banata hai. Pehle toast ke 3.5 second wale timer mein se 3 second beet chuke hon aur doosra toast aa jaaye — cleanup purana timer cancel kar deta hai, isliye naye message ko poore 3.5 second milte hain, aadhe second mein gayab nahi hota.

5 · Escape se dialog band — HotelReg.jsx:17

const onKeyDown = (event) => { if (event.key === "Escape") setShowHotelReg(false); };
document.addEventListener("keydown", onKeyDown);
return () => document.removeEventListener("keydown", onKeyDown);
Sabse aam galti

useEffect data nikaalne ke liye nahi hai. Agar koi value maujooda state se calculate ho sakti hai, to use render ke dauraan hi calculate karo. AllRooms.jsx yeh sahi karta hai — filteredRooms useMemo se banta hai, kisi effect se state mein nahi thoosa jaata. Effects ka kaam hai React ke bahar ki cheezon se sync karna.

Section 13useMemo — mehngi calculation ko cache karna

AllRooms.jsx destination, room type aur price range se filter karta hai, phir sort. Yeh array pe chaar pass hain, aur yeh har render pe dobara chalti — mobile filter drawer kholne pe bhi, jismein sirf openFilters badalta hai.

const filteredRooms = useMemo(() => {
  const matchesDestination = (room) => { /* … */ };
  const matchesRoomType    = (room) => { /* … */ };
  const matchesPrice       = (room) => { /* … */ };

  const sorted = rooms.filter((room) =>
    matchesDestination(room) && matchesRoomType(room) && matchesPrice(room));

  if (sortOption === "Price Low to High")
    return [...sorted].sort((a, b) => a.pricePerNight - b.pricePerNight);
  // …
  return sorted;
}, [rooms, destination, selectedRoomTypes, selectedPriceRanges, sortOption]);

React result ko cache kar leta hai aur tabhi dobara calculate karta hai jab in paanch dependencies mein se koi badle. openFilters jaan bujh ke list mein nahi hai, isliye drawer toggle karne pe wahi cached list reuse hoti hai.

Har jagah mat lagana

useMemo ki apni cost hoti hai — value store karna aur dependencies compare karna. Ise sach mein mehnge kaam ke liye use karo, ya jab stable object reference chahiye ho. Sirf 10 dummy rooms ke saath yeh performance se zyada pattern seekhne ke liye hai — jo bilkul sahi wajah hai isko likhne ki.

Section 14State ko upar uthana (lifting state up)

Jab do components ko ek hi data chahiye, to woh state unke sabse nazdeeki common parent mein chali jaati hai. Yahi problem aakhir mein aapko Context tak le jaati hai.

Prop drilling woh hai jo tab hota hai jab aap state upar to utha do lekin phir haath se neeche pass karte raho:

App → Home → FeaturedDestination → HotelCard   // sirf `currency` pahunchane ke liye

Inme se do components currency use hi nahi karte; woh sirf courier hain. Ab isko ek dozen values se multiply karo aur har component ka signature bakwaas ban jaata hai. Yahi dard Context khatam karta hai.

Section 15Context API — app ka dimaag

Context ek aisi value banata hai jise koi bhi descendant seedha padh sakta hai, chahe kitna bhi gehra ho, bina ek bhi beech ka prop pass kiye.

Teen hisse

1 · Channel banao — context/AppContext.js

import { createContext } from "react";
export const AppContext = createContext(null);

2 · Value provide karo — context/AppProvider.jsx

const value = { currency, navigate, rooms, bookings, hotel, isOwner,
                addRoom, bookRoom, payBooking, cancelBooking, /* … */ };

return <AppContext.Provider value={value}>{children}</AppContext.Provider>;

3 · Use karo — context/useAppContext.js

export const useAppContext = () => {
  const context = useContext(AppContext);
  if (!context) throw new Error("useAppContext must be used inside <AppProvider>");
  return context;
};
Yeh guard clause bahut achhi practice hai

Provider lagana bhool gaye to aapko seedha problem batane wala error milega, na ki kisi bilkul alag component ke andar se aata hua ajeeb sa Cannot destructure property 'rooms' of null.

Aapke context mein kya-kya hai

Kis type kaNaamNote
Datarooms, bookings, hotel, isOwner, showHotelReg, searchedCities, currency, user, currentUserApp ke nouns (cheezein)
ActionsregisterHotel, addRoom, toggleRoomAvailability, bookRoom, payBooking, cancelBooking, rememberCity, notifyVerbs (kaam) — har state change inhi mein se ek se hota hai
QueriesisRoomAvailable, dashboardData se nikale gaye, har render pe dobara bante hain

Yeh structure hi asli seekh hai. Components kabhi seedha state nahi likhte — woh ek action call karte hain, aur action ke paas saare rules hote hain. bookRoom dekho: woh nights ginta hai, total nikalta hai, status aur timestamps lagata hai, aur id banata hai. Component bas itna kehta hai "yeh room book kar do".

const bookRoom = ({ room, checkInDate, checkOutDate, guests }) => {
  const nights = nightsBetween(checkInDate, checkOutDate);
  const booking = {
    _id: createId("booking"),
    user: currentUser, room, hotel: room.hotel,
    totalPrice: room.pricePerNight * nights,
    guests: Number(guests),
    status: "pending", isPaid: false,
    /* … */
  };
  setBookings((prev) => [booking, ...prev]);
  return booking;
};

Derived state: dashboard

const dashboard = {
  totalBookings: bookings.length,
  totalRevenue: bookings.reduce((sum, b) => sum + b.totalPrice, 0),
  bookings,
};

Revenue state mein store nahi hai — woh har render pe bookings se dobara nikalta hai. Yeh sahi decision hai: store kiya hua total us list se out of sync ho sakta hai jiska woh summary hai; derived total kabhi ho hi nahi sakta.

Context ki ek asli cost

Jab provider ki value badalti hai, to har consumer re-render hota hai. Aapka value object AppProvider ke har render pe naya banta hai, isliye wahan ka koi bhi state change useAppContext use karne wale sabhi components ko re-render kar deta hai. Is size pe yeh dikhta bhi nahi. Bade app mein aap ise alag-alag contexts mein baant dete — ek kam badalne wala, ek zyada — ya value ko useMemo mein wrap karte. Trade-off pata hona hi asli baat hai.

Section 16Custom hooks

Custom hook matlab bas ek function jiska naam use se shuru hota hai aur jo doosre hooks call karta hai. useAppContext aapka hai:

// iske bina — lagbhag 14 files mein yeh dohrana padta
const { rooms } = useContext(AppContext);

// iske saath — chhota bhi, aur check bhi karta hai
const { rooms } = useAppContext();

Teen fayde: imports ka kam shor, null check ke liye ek hi jagah, aur ek "seam" — kal ko Context ki jagah Redux ya Zustand lagana ho to aap ek file badloge aur kisi component ko pata bhi nahi chalega.

Rules of Hooks

  1. Hooks sirf top level pe call karo — kabhi if, loop ya nested function ke andar nahi. React hooks ko call ke order se track karta hai, aur conditional calls us order ko bigaad ke state kharab kar dete hain.
  2. Hooks sirf React functions se call karo — components, ya doosre custom hooks se.

Aapke eslint.config.js ka eslint-plugin-react-hooks dono enforce karta hai, aur missing effect dependencies pe bhi warning deta hai. In warnings ko seriously lo — yeh aksar sach mein stale-closure bug bata rahe hote hain.

Rule 1 aapke code mein dikhta hai

RoomDetails.jsx mein bahar wala component pehle useParams() aur useAppContext() call karta hai, aur uske baad hi <NotFound /> return kar sakta hai. Har hook kisi bhi conditional return se pehle chalta hai.

Section 27Khud ko test karo

Agar in sabka jawab yaad se de sako, to samajh lo project aapko samajh aa gaya. Jawab dekhne ke liye click karo.

<AppProvider> ko <BrowserRouter> ke andar hi kyun hona chahiye?

Kyunki AppProvider useNavigate() call karta hai, aur woh hook router context padhta hai. Koi bhi hook sirf woh context padh sakta hai jo uske kisi ancestor ne diya ho. Router ke bahar padhne ko kuch hai hi nahi, isliye React error phenk deta hai.

Rooms list pe key={index} lagane se asal mein kya bigadta hai?

addRoom [room, ...prev] se naya room sabse aage jodta hai, isliye har purane item ka index ek se khisak jaata hai. React samajhta hai ki item 0 ka content badla, na ki naya item insert hua — aur galat DOM nodes reuse kar leta hai, jisse scroll position, focus aur uncontrolled input values purani hi reh jaati hain.

Toast wala effect clearTimeout kyun return karta hai?

Cleanup effect ke dobara chalne se pehle chalta hai. Agar pehle toast ke 3.5 second wale timer mein se 3 second beet chuke hain aur doosra toast aa jaaye, to cleanup purana timer cancel kar deta hai, jisse naye message ko poora time milta hai, aadhe second mein gayab nahi hota. Yeh unmount ke baad timer chalne se bhi bachata hai.

totalRevenue kahan rehta hai, aur woh state kyun nahi hai?

Woh derived hai — bookings.reduce((sum, b) => sum + b.totalPrice, 0), har render pe naya. Store kiya hua total us list se out of sync ho sakta hai jiska woh summary hai; har add, cancel aur edit pe usko update karna yaad rakhna padta. Derived value kabhi bhatak hi nahi sakti.

<RoomDetailsView> pe key={room._id} se kya hota hai?

Rooms ke beech move karne pe woh poora remount force kar deta hai. Iske bina React purana instance reuse karta, aur room B pe room A ki chuni hui photo, dates aur availability result dikhte. Badli hui key ka matlab hai "alag cheez" — purana state poora phenk do.

sorted.sort(…) ki jagah [...sorted].sort(…) kyun?

.sort() jagah pe hi mutate karta hai. Yahan sorted waise bhi .filter() se aaya naya array hai, lekin aadat asli baat hai: kabhi bhi aisi cheez mutate mat karo jo state hai ya aage chal ke state ban sakti hai. Spread pehle copy bana deta hai.

<Link to="/rooms"> aur <a href="/rooms"> mein farak kya hai?

Link click ko pakad ke client-side pe components swap karta hai — turant, aur Context state bacha rehta hai. Anchor poora reload karwa deta hai: bundle dobara download hota hai, React zero se remount hota hai, aur memory ki saari bookings khatam.

AllRooms ke useMemo mein openFilters kyun nahi hai?

Kyunki openFilters sirf yeh control karta hai ki mobile filter drawer dikhe ya nahi — usse yeh farak nahi padta ki kaun se rooms match karte hain. Use daal dete to har baar "SHOW" tap karne pe poora filter-and-sort dobara chalta. Dependencies mein bilkul wahi hona chahiye jo calculation padhti hai, ek bhi zyada nahi.

App ko kaise pata chalta hai ki owner pages pe Navbar aur Footer chhupane hain?

App.jsx useLocation() padhta hai, pathname.startsWith("/owner") nikaalta hai, aur {!isOwnerPath && <Navbar />} render karta hai. Owner section apna shell khud deta hai — Layout.jsx aur <Outlet /> ke through.

createId timestamp aur counter dono kyun use karta hai?

Date.now() millisecond tak hi ja sakta hai, to ek hi millisecond mein bane do records ki id takra jaati — aur duplicate keys reconciliation tod dete hain. Badhta hua counter session ke andar uniqueness pakka karta hai. Asli app mein yeh id database deta.

Chhota sa summary

Aapne ek component tree banaya jo state se render hota hai. Local state local hi raha; jo do components ko chahiye tha woh Context mein chala gaya, jahan data aur actions milte hain, raw setters kabhi nahi. Jo state shareable honi chahiye woh URL mein hai. Effects sirf React ke bahar ki cheezein sambhalte hain — listeners, timers, document body — aur unme se har ek apne peeche saaf-safai karta hai. Lists ke paas pakki keys hain, updates kabhi mutate nahi karte, aur badli hui key woh tarika hai jisse aap jaan bujh ke state phenk dete ho.

Yeh sirf ek hotel booking app jitni knowledge nahi hai. Yeh lagbhag poora React hai.
